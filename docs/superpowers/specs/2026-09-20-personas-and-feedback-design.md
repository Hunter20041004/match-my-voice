# 角色與反哺設計

延伸 `2026-09-08-sample-sourcing-design.md`。那份定義了「怎麼找樣本」；這份加三件事：
**多角色、從修改中學、一個管理介面**。找樣本的流程不變。

## 為什麼

三個想法在 9/20 收斂成一個東西：

1. **多角色**——一個人不只一種口吻。「我」寫報告，「正式的我」寫推薦信，
   「徵才月行銷長」代表組織發文。後者根本不是同一個人的口吻。
2. **反哺**——Agent 寫第一版，使用者自己改到滿意，把改好的貼回來。Agent 比對
   兩版，從改動裡學。使用者不用解釋，改就好。
3. **介面**——角色要看得到、切得動；學到的規則要看得到、撤得掉。對話裡做不到這些。

市場查證（2026-09-20）：英文有 Bloomberry（社群貼文、從修改學）與 Revise AI
（勾選接受／拒絕建議，不是整份比對）；中文市場豆包、Kimi、文心、通義、秘塔、
WPS、笔灵均無「從修改學」功能。「多角色 × 從整份修改學」中英文都沒人做。

## 架構：我們不產內容

```
使用者的 Agent（Claude Code／Codex）
   │  寫東西的是它。用它自己的腦、它自己的授權。
   │
   └─ match-my-voice ＝ 說明書 ＋ 檔案櫃 ＋ 管理頁面
         ├─ SKILL.md、references/     教 Agent 怎麼做
         ├─ ~/.config/match-my-voice/  口吻檔、角色、學習紀錄，全在使用者電腦
         └─ ui/                        一個本機網頁，讀寫上面那個資料夾
```

**這個工具不呼叫任何 AI、不需要 API 金鑰、沒有伺服器、不碰使用者資料。**
所有思考由 Agent 做，我們只提供方法與儲存。

## 角色模型

一個角色 = 一份完整口吻檔（核心習慣、場合模式、涵蓋紀錄，沿用現有模板）。

| 角色類型 | 例子 | 樣本從哪來 | 作者確認問法 |
|---|---|---|---|
| `self` | 我 | 使用者自己寫的東西 | 「這幾份都是你自己寫的嗎？」 |
| `role` | 徵才月行銷長 | 該角色過去的產出，可能多人寫 | 「這幾份是這個角色該有的樣子嗎？」 |

「正式的我」**不是**角色，是 `self` 底下的一個場合模式。角色之間平行、互不繼承。

## 選角色

- 介面上設「目前角色」，Agent 預設用它。
- 對話裡說「用我自己的口吻」「用行銷長的口吻」可臨時換，只影響這一次。
- 沒設過目前角色且只有一個角色 → 用它。多個且沒設 → 問一次。

## 反哺流程

```
Agent 產出第一版  ──→  使用者在自己的編輯器改到滿意  ──→  貼回整份
                                                            │
                     ┌──────────────────────────────────────┘
                     ▼
              Agent 逐句比對兩版
                     │
                     ▼
              把每處改動分類：口吻／事實／長度／結構／其他
                     │
                     ▼
              只對「口吻」類提出規則，當場列出：
              「你把三處『此專案充分展現』改成『我做這個的時候』——
               以後都這樣嗎？」
                     │
              ┌──────┴──────┐
              好            不要
              │              │
         寫進口吻檔      記為一次性修改
         附來源與日期
```

規則：

- **只學口吻。** 修錯字、改事實、刪段落不是口吻訊號，不進口吻檔。
- **當場問，不默默學。** 學錯一條比沒學更糟。
- **改過的句子是使用者的原稿。** 它們比 Drive 裡的舊文件更好——同一任務、同一場合、
  針對 AI 的錯誤寫出來的。分析時比照原始樣本，不比照「被接受的 AI 文字」。
- **沒改的句子是被接受的 AI 文字**，維持現有規則：是 reviewed example，不是人類原稿。
- 每條學到的規則記：規則本身、來源（哪次任務、哪句）、日期、狀態（生效／撤銷）。

## 介面 v1

一個本機網頁，敲一個指令開啟。功能：

| 功能 | 說明 |
|---|---|
| 角色清單 | 列出所有角色，標示目前角色，一鍵切換 |
| 新增角色 | 名稱、類型（self／role）。建好是空的，樣本由 Agent 在對話裡收 |
| 編輯口吻檔 | **直接編輯那份 Markdown**。至少是一個等寬字體的可編輯文字區加儲存鈕；即時預覽可選。看到的就是 Agent 讀到的 |
| 學習紀錄 | 每條學到的規則：內容、來源、日期。可撤銷、可改字 |
| 刪除角色 | 要確認 |

不做：在介面裡寫東西、在介面裡貼樣本、在介面裡跟 AI 對話。那些都在 Agent 對話裡。

**視覺方向在實作前另提 2～3 個選項給使用者挑**，依全域前端規範，不在這份 spec 決定。

## 技術決定（例行、可逆，寫在這裡讓後續一致）

| 決定 | 選擇 | 理由 |
|---|---|---|
| 介面怎麼跑 | 一個小 Node 伺服器 ＋ 單檔 HTML。**伺服器只用 Node 內建模組（http、fs、path），不裝任何套件** | 讀寫本機檔案需要伺服器；Claude Code／Codex 本身就是 Node，使用者一定有；不裝套件才能讓「clone 完直接開」成立 |
| 要不要 build | 不要。Tailwind CDN ＋ CSS 變數 | `git clone` 完直接能開，不用 `npm install`；全域規範對單檔 HTML 允許此例外 |
| 儲存結構 | `~/.config/match-my-voice/` 下：`config.json`（目前角色）、`profiles/<id>/VOICE.md`、`profiles/<id>/learned.md` | 純文字，使用者用任何編輯器都能開 |
| 現有 `profiles/default/` | 自動視為第一個 `self` 角色，不搬不改 | 已有使用者不受影響 |
| 開啟指令 | `node ui/serve.js`（技能資料夾內） | 不裝任何東西 |

## 不做什麼

- 不呼叫 AI、不要 API 金鑰、不做伺服器、不做登入
- 不打包成桌面 App（v1 是本機網頁；之後要包，同一個網頁直接包）
- 不做角色共享或匯出給別人
- 不接 Google OAuth（找樣本沿用 9/8 那份：有連接器用連接器，沒有就貼上／上傳／本機檔案）
- 不在介面裡產內容

## 未驗證項

1. **Agent 逐句比對兩版的準確度**——中文斷句、段落重排、整段重寫時的對應，沒實測。
   驗收時要用真實的「第一版 vs 改後版」跑至少 3 組。
2. **「只學口吻」的分類準不準**——Agent 分辨「換詞是口吻」還是「換詞是修事實」，
   靠的是說明書寫得夠不夠清楚。要靠盲測。
3. Node 版本相容範圍——沒查 Claude Code／Codex 各自要求的最低版本。

## 驗收檢查

一次驗一項：

1. 建兩個角色（一 self、一 role），Agent 能依介面設定的目前角色寫，對話可臨時換。
2. `role` 類角色收樣本時，作者確認問的是「該有的樣子」，不是「你寫的嗎」。
3. 貼回改後版，Agent 列出的規則只含口吻類改動；修錯字、改數字不出現。
4. 對規則說「不要」，口吻檔不變；說「好」，口吻檔多一條並附來源與日期。
5. 介面能看到那條規則，撤銷後 Agent 下次寫不再套用。
6. 介面直接改口吻檔文字，Agent 下次讀到的是改後的。
7. `git clone` 後不裝任何東西，`node ui/serve.js` 能開介面。
8. 既有的 `profiles/default/VOICE.md` 使用者升級後不需搬檔。
9. 口吻檔、學習紀錄、config 都不在版控內（沿用現有 `.gitignore`）。
10. 介面截圖自檢通過（桌機 1280×800、手機 375×812，依全域前端規範）。

這些證明流程照設計運作，**不證明產出更像本人**——那仍以多人盲測為準。
