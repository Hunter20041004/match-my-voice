# 口吻靠可量測訊號守住，不靠 LLM 猜

> 讀法說明：本報告每一項主張後面都掛一個證據等級——**【有文獻證實】**（有同行審查論文、官方文件或模型卡直接陳述）、**【有實作但未經評測】**（有程式碼或產品存在，但沒有量化評測）、**【推論】**（研究員或本報告根據證據拼接推導，非任何來源直接說的）。另有 **【Gap】** 標示筆記明確查不到證據的地方。所有技術名詞第一次出現時，括號內附一句白話解釋。研究筆記日期基準為 2026-09-21。

一個「讓 AI 用本人口吻寫作」的工具，底層方法論應該是**三層分工**：工具本身只做確定性的統計與比對（字元層級的文體計量、字元級差異比對、多路訊號儀表板），把需要「理解語意」的工作交給使用者已經在用的 Claude／Codex 代理人依書面指令執行，並把所有學到的東西寫進一份人看得懂、改得動的口吻檔案——這份檔案是唯一的真相來源，不是任何模型內部的權重或向量。四份研究筆記查到的證據支持這條路線的每個零件：中文文體計量的共識是「以字為單位優於以詞為單位」【有文獻證實】；LLM 直接判斷作者風格會把「同話題」誤認成「同作者」，但加上語言學引導指令後可以大幅逆轉【有文獻證實，英文】；從使用者編輯推論偏好可以不訓練模型、只靠自然語言描述加檢索（PRELUDE／CIPHER）【有文獻證實】；「像不像」可以算成數字，但三類常見指標彼此幾乎零相關，所以必須多路並列、不能合成單一分數【有文獻證實，英文】。同樣重要的是筆記標出的空白：**沒有任何方法在「2,000–5,000 個中文字」這個規模被驗證過**；「改口吻／改事實／改長度」的規則式分類器沒有任何文獻背書；中文沒有編輯意圖標註語料；沒有論文證明「編輯訊號比寫作樣本更有效」。因此「本機累積的 (草稿, 修改) 對」是真實的資料取得優勢與產品定位優勢，但**不是被證明的效果優勢，也不是雲端廠商技術上做不到的事**。誠實的結論是：這個產品沒有 Spotify 式的技術突破，它的價值來自把幾個各自成熟的零件第一次組進「本機、代理人外掛、人可讀檔案」這個形式裡，並用確定性驗證層補上 LLM 模仿的已知弱點。

## 中文口吻要從字、虛詞和全形標點算起，LLM 直覺會把話題當風格

### 傳統文體計量在中文的適用性：字元優先，但小樣本與繁體證據是空白

Stylometry（文體計量：用統計方法數一篇文章裡可數的東西——字、詞、標點、句長——來辨認是誰寫的）在英文已高度成熟，核心特徵包括 function words（虛詞：the／of／and 這類本身沒有實質意義、只負責語法的詞）、character n-gram（字元 n 連：把文字切成連續 n 個字的小片段，例如「我覺得」的 2 連是「我覺」「覺得」）、詞性序列、句長分佈、標點頻率、TTR（詞彙豐富度：不同詞的數量除以總詞數）以及 Burrows' Delta（一種距離公式，比較兩篇文章在高頻字用法上差多遠）。中文文獻的共識很清楚：**字元層級的特徵系統性優於詞層級**，原因是中文斷詞（把連續的漢字切成一個個詞）本身有誤差、會污染詞級特徵，而單一漢字常常自帶語意與語法功能 ([N-Gram-Based Author Profiles](https://wiki.eecs.yorku.ca/course_archive/2014-15/W/6339/_media/10_1_.1.1.87.754.pdf))【有文獻證實，跨語言實驗含中文，年代較舊】。Cambridge 專書《Authorship Analysis in Chinese Social Media Texts》同樣陳述字元 n-gram 已被證實系統性優於虛詞法 ([Cambridge Elements](https://www.cambridge.org/core/elements/authorship-analysis-in-chinese-social-media-texts/CDFBDEE28085274DE8E3FEA3921AFD06))【有文獻證實，筆記僅取得摘要層級】。Burrows' Delta 在中文上唯一的實證案例是 2024 年一篇針對唐代 20 位詩人的研究：以「字元」取代「詞」為單位、取前 100 個最高頻字元當特徵，用 stylo 套件（一個做文體計量的 R 語言工具）就能把同一位詩人的作品完全正確聚在一起 ([arXiv:2407.08099](https://arxiv.org/html/2407.08099))【有文獻證實】。但同一篇論文自陳兩個限制：結果對「樣本怎麼切」很敏感，而且**完全沒有測試小樣本**，作者自己呼籲後續研究去找方法失效的門檻【有文獻證實】。

中文特有的訊號裡，句末助詞（了、呢、吧、啊、啦、嗎）在語言學上被定義為「不帶指涉意義、但關聯語氣與語域」的詞類 ([Wikipedia: Sentence-final particle](https://en.wikipedia.org/wiki/Sentence-final_particle))【有文獻證實其語言學定義，非作者歸屬實證】；「的」是定語標記、「了」是體標記，這些正是中文版的 function characters（功能字：中文裡扮演虛詞角色的單字）。專門研究中文虛詞作者歸屬的論文確實存在 ([Function Words for Chinese Authorship Attribution, ACL 2012](https://aclanthology.org/W12-2506.pdf))，但研究員無法解析該 PDF，**拿不到具體特徵清單與準確率**【有文獻證實其存在，數字未取得】；同樣狀況也發生在 LREC 2022 的《A Reproducible Corpus for Chinese Authorship Attribution》 ([ACL Anthology](https://aclanthology.org/2022.lrec-1.633.pdf))【有文獻證實其比較了字元 n-gram、詞 n-gram、詞性、標點，數字未取得】。三個明確的空白：全形標點（，。「」！？…）作為中文特有標點系統，理論上是強特徵，但**沒有任何專門實證研究**【Gap】；TTR 在中文的可比性未查到【Gap】；PAN（作者驗證領域最權威的國際共享評測任務，2013 年起每年舉辦）的主線任務歷來以英文為主，中文只出現在同一實驗室底下的「多語文本去毒化」子任務，從未進入作者驗證主線 ([Overview of PAN 2024](https://downloads.webis.de/publications/papers/bevendorff_2024b.pdf))【有文獻證實】。這代表：**繁體中文（台灣）的文體計量，目前沒有任何權威公開評測可以直接引用**。

對本產品最重要的實務含意是【推論】：字元 n-gram、功能字頻率、句末助詞、句長分佈、標點頻率這些「淺層計數特徵」，全部可以用純規則與字典統計算出來，不需要任何神經網路，天然適合寫成「這個人平均每句 18 個字、每千字用 12 次『吧』、驚嘆號佔標點 4%」這種人類可讀規則。這與英文文體計量的傳統一致，只是把單位換成字元。

### 內容無關的風格向量：技術存在、模型很小，但中文覆蓋四份筆記說法不一

Content-independent style representation（內容無關的風格表徵：把一段文字壓成一串數字——也就是 embedding／向量——而且這串數字只反映「怎麼寫」、不反映「寫什麼」）是 2021–2025 年同一群研究者的連續迭代：STEL → LUAR → Wegmann CISR → StyleDistance → mStyleDistance。共同手法是 contrastive learning（對比學習：讓模型看大量「同一人寫不同主題」與「不同人寫同一主題」的配對，逼它學到跟主題無關的差異）加上某種內容控制。Wegmann 等人 2022 年的關鍵發現是：既有風格模型多用「兩篇是不是同作者」當訓練目標，但同一作者常寫同類話題，模型可能學到的是主題而非風格；解法是在訓練時加入「對話／領域標籤」控制內容，結果用對話層級控制的版本，比領域層級或不控制的版本更能分離風格與內容 ([arXiv:2204.04907](https://arxiv.org/abs/2204.04907))【有文獻證實】。StyleDistance 進一步用 LLM 生成「近乎精確的釋義對」（同一句話換說法但意思完全不變），在 40 種風格特徵上製造正負例，專門解決「傳統對比配對常常風格和內容一起變」的內容洩漏問題 ([arXiv:2410.12757](https://arxiv.org/abs/2410.12757))【有文獻證實】。

模型規模都不大，這對「本機、無 GPU」（GPU 是顯示卡上的運算晶片，訓練與大量推論 AI 模型時通常靠它加速；沒有 GPU 就只能用一般處理器 CPU）的限制是好消息。LUAR-CRUD 是 **82.5M 參數**（參數量是模型大小的單位，1M＝一百萬），官方模型卡標註語言為英文，範例程式碼會在沒有 GPU 時退回 CPU ([Hugging Face: LUAR-CRUD](https://huggingface.co/rrivera1849/LUAR-CRUD))【有實作，模型卡一手陳述】；StyleDistance 是 **0.1B 參數**（1B＝十億）、底座 roberta-base、MIT 授權（可自由商用的開源授權）、標註英文 ([Hugging Face: StyleDistance](https://huggingface.co/StyleDistance/styledistance))【有實作】；mStyleDistance 是 **0.3B 參數**、底座 xlm-roberta-base（一個名義上涵蓋約 100 種語言的多語模型），在 mSynthSTEL 合成資料集上以 9 種非英語語言訓練，論文發表於 ACL Findings 2025 ([arXiv:2502.15168](https://arxiv.org/abs/2502.15168)、[Hugging Face: mStyleDistance](https://huggingface.co/StyleDistance/mstyledistance))【有文獻證實】。此外有一篇對 LUAR 類方法的批判性複驗指出：這類模型在驗證任務上準確率高，**但未必真的捕捉到人類定義的具體風格特徵** ([arXiv:2308.11490](https://arxiv.org/pdf/2308.11490))【有文獻證實】。

這裡必須誠實指出一個**四份筆記互相不一致**的地方：Q1 筆記依論文摘要判定 mStyleDistance 的 9 種語言「含中文」、稱它是唯一「明確涵蓋中文＋做過中文評測＋開源」的模型；Q3 與 Q4 筆記查 Hugging Face 模型卡，只看到日文示範、**未明列中文**，將其定為「架構上宣稱、但未找到中文專屬評測」。兩邊都沒有查到 mSynthSTEL 的中文子集是簡體還是繁體【Gap】。本報告的判讀是：mStyleDistance 是目前**唯一有機會**用在繁體中文上的內容無關風格模型，但「有機會」到「能用」之間，必須由本產品自己在繁體中文語料上做一次校準測試才能確認。CPU 推論速度方面，三個模型都**沒有官方 CPU 延遲數字**【Gap】；「0.1–0.3B 的編碼器在筆電 CPU 上處理幾十篇文件是數秒到數十秒等級」是研究員根據同類模型經驗做的推論，不是實測【推論】。最後，這整條路線的產出全都是不透明的高維向量（例如 768 個數字），**沒有一個是人類可讀規則**；要變成可讀口吻檔案，必須額外做「向量→文字」轉譯【推論】。

### LLM 直接判斷的已知弱點：偏向判「不同人」、把話題當風格、抽特徵不穩定

「把文件丟給 LLM 叫它判斷這人怎麼講話」的弱點有直接實測證據。EMNLP 2024 Findings 的《Can Large Language Models Identify Authorship?》明確指出機制：LLM 是在大量不同作者的資料上訓練的，因此**天生較擅長偵測「風格差異」而非「風格相似」**，導致模型偏向判定「不同作者」，並會把「同話題」誤當「同作者」的代理訊號；作者必須用平衡的正負例資料集來緩解這個偏誤 ([arXiv:2403.08213](https://arxiv.org/html/2403.08213))【有文獻證實，英文】。同一篇論文也給出解方：Linguistically Informed Prompting（LIP，語言學引導提示：在指令裡明確要求模型忽略主題內容，只描述詞彙選擇、句構、語氣等語言學層次特徵）。加上 LIP 後，**GPT-4 Turbo 在 Blog 資料集的作者驗證達 84.45% weighted F1，BERT 基準只有 42.22%**；Email 資料集 20 人作者歸屬，**GPT-4 Turbo + LIP 達 77.22%，BERT 21.67%，TF-IDF 只有 1.20%–5.95%**【有文獻證實，單一研究、英文、尚無獨立複驗】。更關鍵的是，加了 LIP 後 GPT-4 的判斷依據會聚焦在「幽默、諷刺、隨性、口語」這類具體語言學特徵詞——換句話說，**LLM 若被明確要求用語言學術語解釋風格，其輸出本身就是人類可讀的**【有文獻證實，僅此一篇設計】。

模仿面的弱點同樣有證據。Digital Scholarship in the Humanities 期刊的研究發現 GPT-4o 能捕捉知名作家的表層特徵，**但難以複製深層的文體計量簽名** ([DSH](https://academic.oup.com/dsh/article/40/2/587/8118784))【有文獻證實】；2025 年的《Catch Me If You Can? Not Yet》標題直接點出 LLM 在模仿「一般人（非名家）的隱性寫作習慣」上仍然表現不佳，且在部落格、論壇這類非正式文體上比新聞、email 差 ([arXiv:2509.14543](https://arxiv.org/abs/2509.14543))【有文獻證實核心論點，具體數字未取得】。Q3 筆記補上了 LLM 當「評審」的不穩定性：PersonalBench 讓 LLM 從同一位作者的樣本重複抽取風格特徵，**抽出的特徵集合平均 Jaccard 相似度只有 0.22**（Jaccard 是「兩個集合重疊比例」，0.22 代表每次抽的特徵八成不一樣），而且存在「循環論證」問題——如果生成方用來建立作者輪廓的方式跟評審抽特徵的方式雷同，量到的是「有沒有照指令做」而不是「風格有沒有轉移」 ([PersonalBench, arXiv:2608.19746](https://arxiv.org/html/2608.19746v1))【有文獻證實，英文】。針對**中文文本**的 LLM 作者判斷實測論文：一篇都沒有【Gap】。

### 把內容跟風格分開的三個層級：規則層免模型、指令層交給代理人、模型層只能重用權重

綜合 Q1 筆記，分離技術可以依「需不需要訓練」分三層，而這個分層直接決定了本產品哪些能做。**規則層**：只統計虛詞、句末助詞、標點、句長——這些特徵天然對主題不敏感，因為任何主題的文章都會用「的」和句號，用法主要受個人語感支配【有文獻證實為成熟路線，中文具體數字未取得】。Topic masking（主題遮蔽：把內容詞蓋掉只留功能詞再分析）有專門論文 ([An Improved Topic Masking Technique](https://www.researchgate.net/publication/341046337_An_Improved_Topic_Masking_Technique_for_Authorship_Analysis))【有文獻證實其存在，僅摘要層級】——筆記中提到的「遮蔽後 F1 約 0.79」這個數字，研究員自陳無法鎖定原始出處，**本報告不採用**。**指令層**：LIP 式的「請忽略主題、只描述語言學特徵」指令，完全不需要訓練，直接寫進給代理人的指令文件即可；它在精神上就是 Wegmann 訓練期內容控制的「推論期版本」【推論】。**模型層**：mStyleDistance 這類對比學習模型，訓練這件事本身不可能用文字指令複製，只能重用已發布的權重當交叉驗證工具【推論】。這個分層的結論是：**口吻提煉的主幹可以用「規則統計＋LIP 指令」完成、完全不自己訓練模型**，mStyleDistance 是可選的加分項而非必要品。

### 人可讀規則：有兩條學術路線，但「中文＋可讀＋口吻檔案」的交集是文獻空白

把風格提煉成結構化、人可讀的規則（而非向量）是 2024–2026 年一個明確的新興子方向。第一條是 **Biber 式可解釋特徵**：Neurobiber 建立在 Biber 多維分析（一個語言學界成熟的文體分析框架）上，可預測 **96 種**可解釋特徵（代名詞、被動語態、情態動詞、話語標記等），比既有開源系統快 **56 倍**，神經網路代理模型對規則式標準答案的預測達 **0.97 macro-F1**——證明 Transformer 可以高保真地模仿人工設計的語言學規則 ([arXiv:2502.18590](https://arxiv.org/abs/2502.18590))【有文獻證實】；但 Biber 框架是為英文設計，**沒有查到中文版或中文特徵移植**【Gap】。第二條是**向量轉文字的解碼路線**：《Interpreting Style Representations via Style-Eliciting Prompts》建立 1,010 種風格特徵的資料集，訓練一個解碼器把風格向量反推成「可以直接拿去引導 LLM 生成同款風格」的自然語言指令，論文指出直接叫 LLM 描述風格「容易受幻覺與偏誤影響、缺乏明確目標函數」，而解碼器路線在三個任務上全面優於直接描述 ([arXiv:2606.05716](https://arxiv.org/pdf/2606.05716))【有文獻證實】——但這需要先有訓練好的解碼器，本產品做不到。StyleRemix 用 LoRA（一種小型、可插拔的模型微調模組）沿「正式度、長度、諷刺程度」等可命名的風格軸改寫文本，自動與人工評測都超越更大的 LLM ([arXiv:2408.15666](https://arxiv.org/abs/2408.15666))【有文獻證實】——「風格軸＝可各自調整的滑桿」這個概念可以直接借進口吻檔案的設計，LoRA 本身不必做【推論】。市面上「用 Claude 從個人文章產生 style guide」的教學文章存在 ([Medium](https://medium.com/@anticodeguy/create-your-writing-style-guide-with-claude-ai-78c559c7ea65))【有實作但未經評測】，沒有任何準確度或穩定性數據。最終判定：**「自動從個人歷史文件生成結構化、可編輯的中文口吻檔案」這個交集，沒有任何論文或開源專案**【Gap】，只能靠組合現有零件自行設計。

關於多人格（persona）的設計，Q3 筆記推導出一個重要的失效模式【推論】：功能字之所以是穩健的風格標記，正因為它「低於作者自覺控制」；但同一個人寫正式報告與隨性聊天時，功能字分佈本來就會系統性改變，這種合理的語域轉換會被儀表板誤判成「風格漂移」。這反過來成為 persona 分離的方法論理由：**每個 persona 就是一個「語域受控」的獨立語料，各自建立基準線與檔案**，而不是把所有文字混在一起算平均。至於「依角色類型語意自動分離人格」這個機制，四份筆記**完全查無文獻或產品先例**【Gap】，它是工程設計選擇，不是已驗證的技術。

## 編輯是偏好訊號，但「改口吻／改事實／改長度」的規則分類器沒人驗證過

### 編輯意圖分類：英文有成熟體系，中文是零

從「AI 草稿 vs 使用者修改版」學習，第一步是知道「這一處修改是在改什麼」。目前最成熟、可直接借用的分類體系是 IteraTeR（ACL 2022）的五類：MEANING-CHANGED（改了意思）與 NON-MEANING-CHANGED，後者細分 FLUENCY（修文法）、CLARITY（更精簡易懂，資料集中最常見）、COHERENCE（更連貫）、STYLE（傳達作者的情緒、語氣、聲音） ([ACL Anthology](https://aclanthology.org/2022.acl-long.250/)、[arXiv:2203.03802](https://arxiv.org/abs/2203.03802))【有文獻證實】。語料庫有 **4,018 筆**句級對齊並標籤的編輯，來源是英文 Wikipedia、arXiv 摘要、Wikinews 的修訂歷史【有文獻證實，inter-annotator agreement 數字未取得】。Grammarly 的 CoEdIT 直接沿用其中四個非語意類別，轉成自然語言指令、用 82K 筆指令微調 T5 模型，效果比更大的 LLM 好、模型卻小 60 倍 ([arXiv:2305.09857](https://arxiv.org/abs/2305.09857))【有文獻證實】。更早的 Yang 等人 2017 年為 Wikipedia 建了更細的 13 類語意編輯意圖，分類器 micro-F1 0.621 ([ACL D17-1213](https://aclanthology.org/D17-1213/))【有文獻證實】。**這整條研究線完全沒有中文版本**——搜尋「中文 修訂 語料庫 編輯 意圖」只回傳中研院平衡語料庫這類一般資源，沒有一個是編輯意圖標註【Gap】。實務含意【推論】：五類的**定義**可以直接翻譯成給代理人的繁中判準與範例，但沒有任何中文標註資料或中文微調模型可以依賴。

### PRELUDE／CIPHER：不用訓練就能從編輯學偏好，但「LLM 做摘要」這步要交給代理人

PRELUDE（NeurIPS 2024）把「從使用者歷史編輯推論潛在偏好」正式化為一個框架，CIPHER 是配套演算法：用 LLM 把每次編輯轉成一段自然語言的「偏好描述」，之後面對新情境時，用 retrieval（檢索：從歷史紀錄裡撈出最相似的幾筆）找出 k 個最相似的過去情境，把對應的偏好描述聚合進 prompt 餵給生成模型；**整個機制不需要 fine-tuning**（微調：用新資料更新模型內部參數）；而且因為偏好是以自然語言儲存，使用者可以查看並修改 ([arXiv:2404.15269](https://arxiv.org/abs/2404.15269))【有文獻證實】。這正是「人可讀、可編輯的口吻檔案作為真相來源」這個設計哲學的學術依據。評測方面，CIPHER 在摘要與 email 撰寫兩個任務上以 GPT-4 模擬使用者，在編輯距離成本上是所有比較方法中最低的【有文獻證實方向，精確百分比未取得】；官方程式碼 ([GitHub: gao-g/prelude](https://github.com/gao-g/prelude)) 的 README 沒有偏好描述的實際範例文字、也沒標示檢索用的 embedding 模型【有實作但未經評測】。

CIPHER 對本產品有一個必須正面處理的衝突：「把編輯轉成偏好描述」這一步**需要呼叫 LLM**。在「工具本身不呼叫 AI」的限制下，唯一相容的做法是：工具負責算出字元級差異與確定性訊號，然後由正在對話的 Claude／Codex 代理人依工具提供的書面指令，把差異摘要成一句偏好描述，寫入口吻檔案前向使用者確認一次【推論】。檢索那一步，若用關鍵字或長度相似度可以純規則；若要用語意相似度（cosine similarity：兩個向量夾角的餘弦值，越接近 1 越相似），則需要一個小型本機 embedding 模型【推論】。Q4 筆記查閱 CIPHER 全文後確認了一件對 Q4 結論很關鍵的事：**CIPHER 的所有 baseline 都不包含「只給寫作樣本、不給編輯歷史」這一組**，因此該論文無法證明「編輯訊號比樣本訊號更有效」 ([arXiv:2404.15269 HTML](https://arxiv.org/html/2404.15269v3))【有文獻證實此比較不存在】。

### (草稿, 修改) 當偏好資料：DPO 路線做不到，「當檢索式範例」是唯一可行路線

把人類修改版當偏好資料確實有先例：《Post-edits Are Preferences Too》（WMT 2024）把譯後編輯視為「優於機器原稿」的隱含偏好，先做 SFT（監督式微調）再接 DPO（直接偏好最佳化：一種讓模型「偏向 A、遠離 B」的訓練法） ([ACL Anthology](https://aclanthology.org/2024.wmt-1.122/))【有文獻證實】。但這需要梯度訓練管線與 GPU，**在本產品的部署限制下完全不適用**【推論】。真正可行的是「編輯當檢索式 few-shot 範例」（few-shot：在指令裡附幾個範例讓模型照著做）：把過去的 (草稿, 修改版) 配對存成本機小資料庫，生成前撈出最相似的幾組塞進代理人的指令當範例，不做任何梯度更新——這是 CIPHER 檢索機制的簡化版【推論】。但要誠實標出：「先摘要成偏好描述再檢索」與「直接塞原始配對」哪個效果更好，**沒有任何論文做過對照實驗**【Gap】；EMG-RAG 這類可編輯記憶圖框架存在 ([arXiv:2409.19401](https://arxiv.org/pdf/2409.19401))【有文獻證實其存在】，但沒有用在寫作風格場景評測過。

### 中文句子對齊與 diff：字元級對齊有成熟前例，可拼成幾乎全規則的管線

中文沒有天然詞邊界，處理「版本 A vs 版本 B」最成熟且情境最接近的工具來自中文文法糾錯領域的 ChERRANT：對兩個中文句子做**字元級對齊**（而非詞級，避免斷詞誤差污染差異判定），把差異歸為代換（S）、遺漏（M）、多餘（R）、語序（W）四類，其中 W 是英文版沒有的中文專屬設計 ([CGEC Survey, arXiv:2504.00977](https://arxiv.org/html/2504.00977v1))【有文獻證實】。句子層級對齊則可借雙語對齊的兩條經典路線：Gale-Church（假設對應句子長度相關）與 Vecalign 類（用 embedding 相似度） ([ACL J93-1004](https://aclanthology.org/J93-1004/))【有文獻證實，雙語情境】。Q2 筆記據此拼出一條**幾乎全部可寫成確定性指令**的管線【推論】：用「。！？」等正規表示式切句 → 句數一致時用位置與長度粗對齊 → 只有句數不一致（有合併、拆分、整句增刪）時才動用 embedding 重新對齊 → 每對句子內用 Python 標準庫 difflib 以單一漢字為單位做字元級 diff（差異比對）。這個分層設計把「需要模型」的頻率壓到最低，因為多數編輯是同句修改。一個技術細節要留意：difflib 用的是 Ratcliff/Obershelp 演算法，跟 git diff 用的 Myers 演算法不同，邊界情況輸出可能不一致，精確度要求高時要實際比較【推論，一般技術知識】。專門為「中文修訂稿對齊」設計並發表評測的論文：零【Gap】。

### 不靠 LLM 區分「改口吻／改事實／改長度」：訊號都能算，但沒有任何文獻驗證這種分類器

這是**四份筆記中證據最薄弱的一塊**，必須原樣呈現。可用的確定性訊號有：長度比（字元數比值）、標點變化次數、功能字頻率前後差異——三者純計數，不需模型【推論】；數字／專有名詞是否被更動——正規表示式抓數字即可，若要抓人名地名可用 NER（命名實體辨識：自動標出文字裡的人名、地名、機構名）小模型 ckiplab/bert-tiny-chinese-ner ([Hugging Face](https://huggingface.co/ckiplab/bert-tiny-chinese-ner))【有實作，無延遲數字與此用途評測】；語意相似度——需要小型中文可用的 embedding 模型，multilingual-e5-small 是 12 層、384 維、含中文，官方文件指出少量句子 CPU 推論即可 ([Hugging Face](https://huggingface.co/intfloat/multilingual-e5-small))【有文獻證實】，bge-small-zh 是 BAAI 專為中文設計的小模型，但**確切維度與參數量未查到** ([BGE 文件](https://bge-model.com/bge/bge_v1_v1.5.html))【有實作但未經評測】。可用的標準答案來源：IteraTeR 的 MEANING-CHANGED 標籤概念上就是「事實編輯 vs 非事實編輯」【有文獻證實，但原論文用的是訓練式分類器】；《Can You Make It Sound Like You? Post-Editing LLM-Generated Text for Personal Style》設計了明確區分「風格編輯 vs 事實修正」的標註方案，並發現使用者編輯時展現一致的風格偏好 ([arXiv:2604.24444](https://arxiv.org/pdf/2604.24444))【有文獻證實其存在，英文 Reddit，方法細節未取得】。但結論是：**沒有任何論文把「實體／數字保留＋embedding 相似度＋長度比＋功能字變化＋標點變化」組成規則式分類器，並拿人工標籤做 precision／recall／F1 評測**【Gap】。這塊沒有現成文獻可背書，必須自行小規模驗證——與使用者全域規則「先用已知答案校準測量方法」完全一致。

「先確認再記錄」的時機，HCI 文獻給了可引用的原則：確認過於頻繁會造成挫折，頻率應隨情境調整 ([PrefIx, arXiv:2602.06714](https://arxiv.org/html/2602.06714v1))【有文獻證實】；使用者偏好往往是「在互動中被建構」而非「本來就存在等著被問」，不宜密集直接提問 ([arXiv:2606.30863](https://arxiv.org/pdf/2606.30863))【有文獻證實】；經典的 adaptable（使用者主導調整）vs adaptive（系統自動調整）區分 ([Kobsa](https://ics.uci.edu/~kobsa/papers/2004-HCI-Encyclopedia-kobsa.pdf))【有文獻證實框架，套用到本產品為推論】。推導出的原則【推論】：**只在準備把某個偏好寫入長期口吻檔案時確認一次，單次生成內的小修改不逐次確認**；針對文字編輯場景的「何時該確認」實證研究，沒有【Gap】。

## 「像不像」算得出數字，但三種指標互不相關、且五千字太少

### 作者驗證的成熟指標與最短長度：有標準可借，但沒有一個在中文小樣本上驗證過

Authorship verification（作者驗證：判斷兩段文字是不是同一人寫的）領域的 PAN 任務用五個指標的平均分排名：AUC（分類器整體區分能力，1 為完美）、c@1（允許系統對困難案例「不作答」而不被扣分的準確率變體）、F1、F0.5u（更重視正確判定「同一作者」）、Brier（機率預測的校準程度） ([ceur-ws paper-245](https://ceur-ws.org/Vol-3740/paper-245.pdf))【有文獻證實，研究員自評信心中等，因未能直接讀取 PAN overview 全文】。c@1 的設計思路對產品有直接價值【推論】：與其硬給「像／不像」二元答案，不如做三態（像／不像／不確定，交給人看），內部驗收指標可直接借 c@1 的計分邏輯。最短長度方面，Eder 2015 的經典結論是可靠作者歸屬需要 **2,500–5,000 個詞**（依語料而異），且這個門檻「與方法無關」 ([Eder, DSH](https://academic.oup.com/dsh/article-abstract/30/2/167/390738))【有文獻證實，以字母語言的「詞」為單位】。2026 年的 AuthBench 是目前最大的多語（10 種語言含中文）作者驗證基準：428,150 份文件、153,825 位作者；驗證任務的 EER（等錯誤率：誤判與漏判相等時的錯誤率，越低越好）從短文本（1–10 token）的 **0.104** 改善到超長文本（>500 token）的 **0.048**，整體最佳 EER 0.076、AUC 0.968，論文明言短文本是「最明顯的瓶頸」——但**沒有拆出中文子集的獨立數字** ([AuthBench, arXiv:2609.06771](https://arxiv.org/html/2609.06771))【有文獻證實】。

### 分佈距離：Delta 有中文案例但規模差兩個數量級，chi-square 明確不能用

Burrows' Delta 的中文實證（前述唐詩研究）所用語料是「單一詩人全集對半切」，最多產的白居易共 229,346 字，**遠大於本產品情境的 2,000–5,000 字，且論文自陳未測小樣本** ([arXiv:2407.08099](https://arxiv.org/html/2407.08099))【有文獻證實】。Evert 等人 2017 年的分析指出「特徵向量正規化」是改善 Delta 表現的決定性因素，且不同 Delta 變體在不同語言與語料下沒有永遠最優的一個 ([Evert et al., DSH](https://academic.oup.com/dsh/article/32/suppl_2/ii4/3865676))【有文獻證實，未討論中文】；Cosine Delta、Eder's Delta 在中文上的驗證：零【Gap】。JS divergence（一種衡量兩個機率分佈差多遠的對稱指標，值域 0 到 1）曾用於莎士比亞時代劇作的作者分群，發現作者風格對用詞變化的解釋力超過悲喜劇分類 ([PLOS One](https://journals.plos.org/plosone/article?id=10.1371%2Fjournal.pone.0111445))【有文獻證實，英文】；套在中文功能字分佈上的研究：零【Gap】。有一個明確的「不要做」：Kilgarriff 證明 chi-square（卡方檢定：一種判斷兩組頻率差異是否顯著的統計檢定）不適合比較文本詞頻，因為它假設樣本互相獨立，但同一篇文章裡的詞彼此並不獨立 ([Kilgarriff 1996](https://www.kilgarriff.co.uk/Publications/1996-K-CHumBergen-Chisq.txt))【有文獻證實，英文】；這個論證是統計性質、與語言無關，因此**任何「逐字做卡方檢定找出哪些字用得跟平常不一樣」的設計都應避免**，改用 z-score 或排序式方法【推論】。

### 風格向量距離：沒有公開門檻，唯一參照值是英文、每人兩萬字以上

LUAR、Wegmann、StyleDistance 三個系列都只回傳一個 cosine similarity，**沒有任何一個公開「相似度多少代表同一人」的通用門檻**【有文獻證實】。唯一接近門檻的數字來自 PersonalBench（2026）與其姊妹論文：在英文 Blog Authorship Corpus 上（50 位作者、每位 ≥200 篇訓練貼文，也就是每人至少兩萬字），**同作者上限 cosine 0.756、跨作者隨機真人下限 0.626，而各種 LLM 人格化方法生成的文字與真實作者的相似度只有 0.484–0.508，低於隨機兩個真人之間的下限**；生成文字彼此之間很容易被分開（AUC 0.918），生成文字 vs 真實作者卻分不太開（AUC 0.632）——代表「LLM 自己的筆跡」比「目標作者的筆跡」訊號更強 ([PersonalBench, arXiv:2608.19746](https://arxiv.org/html/2608.19746v1))【有文獻證實，全英文，論文自陳「不同語言的風格模式可能不同」】。LUAR 單篇 AUC 0.76、5 篇聚合後 0.96 ([arXiv:2604.26460](https://arxiv.org/html/2604.26460))【有文獻證實，英文】；且 LUAR 的 domain gap（域偏移：訓練資料與實際使用資料的格式落差）已被明確記錄——它在 Reddit 上訓練、從未見過 LLM 生成文字【有文獻證實】。正確做法【推論】：**不套用 0.626 這種跨語料常數，而是用使用者自己的歷史文字量出「同一人不同文章之間的相似度分佈」當個人基準線**，再拿候選文字跟這條線比——沒有文獻直接驗證「自建基準線」，但這是唯一能避開域偏移與語言差異的校準方式。

### 最重要的發現：三類指標兩兩相關性接近零，所以不能合成單一分數

PersonalBench 用三個「鏡頭」評測風格相似：LUAR cosine、LLM-as-judge（讓 LLM 先從樣本抽 5 個是非題式風格特徵再逐項打分）、自動文體計量（60 個功能詞與 10 種標點的 cosine similarity）。**三組指標兩兩之間的相關性 |r| < 0.07**（例如 LUAR↔LLM 評審 r = 0.013，LUAR↔功能詞 r = 0.026），論文原文結論是「沒有單一指標能可靠地代表另一個指標」；LLM 評審本身未曾用人類判斷驗證 ([arXiv:2608.19746](https://arxiv.org/html/2608.19746v1))【有文獻證實】；姊妹論文用 GLM-4 32B 當評審得到同樣近零的相關性（LUAR–TMR 介於 -0.049 到 0.075） ([arXiv:2604.26460](https://arxiv.org/html/2604.26460))【有文獻證實】。順帶釐清：LaMP 雖常被當「個人化」代表性基準，但它測的是任務表現（分類準確率、ROUGE），**不是**「聽起來像不像這個人」 ([LaMP, ACL 2024](https://aclanthology.org/2024.acl-long.399/))【有文獻證實】，不能拿來佐證風格漂移。這個發現的產品含意是本報告對 Q3 最核心的回答【推論】：**「像不像」可以變成確定性的數字，但不能變成一個數字**。正確設計是多路訊號各自獨立顯示（功能字與標點分佈的 z-score 偏移、平均句長偏移、embedding 距個人基準線多遠），讓使用者看多個訊號自己決定，而不是合成一個假裝很準的總分。

Z-score 儀表板（z-score：某特徵離「這個人平常的平均值」有幾個標準差）本質上就是 Burrows' Delta「攤開」成逐特徵版本，Delta 內部第一步就是對每個特徵算 z-score 再加總 ([stylo: dist.delta](https://search.r-project.org/CRAN/refmans/stylo/html/dist.delta.html))【有文獻證實方法論根基】；因此只要 Delta 成立，儀表板的每一項數字在方法論上也站得住，差別只在不加總。開源實作 stylometric-transfer 做的正是「JSON 指紋＋本機量測＋偏移報告」 ([GitHub: ngpepin/stylometric-transfer](https://github.com/ngpepin/stylometric-transfer))【有實作但未經評測，無任何準確率或使用數據】。已知失效模式【推論】：語域轉換誤判（前述 persona 議題）；小樣本下單一功能字出現次數可能只有個位數，z-score 分母不穩、數字會因抽樣噪音劇烈跳動。

### 樣本量的現實：沒有任何方法在「3–5 份文件、2,000–5,000 中文字」被驗證

把所有數字放在一起看，這是本題最大的單一空白【Gap】：Eder 的門檻以字母語言的「詞」計，中文字元的資訊密度更低，2,000–5,000 個中文字很可能落在門檻低標以下或邊緣【推論，常識性換算】；中文 Delta 案例大兩個數量級；PersonalBench 參考文本大一個數量級以上。務實結論【推論】：在這個規模，只有功能字／標點這類「封閉集合」特徵（固定 60 個詞、10 種標點，每個在幾千字裡還能累積到有意義的次數）適合當**相對趨勢訊號**；Delta 總分與 embedding cosine 都應視為高變異、僅供參考。但要同時記住 PersonalBench 的另一半：封閉集合指標與「像不像」的人類／模型判斷幾乎不相關——**穩定不等於有效**，這兩個獨立面向必須一起權衡。Q3 筆記另標出一條值得深挖但無數字的路線：「幫每位作者訓練一個小型字元級語言模型，用候選文字在該模型下的 perplexity（困惑度：模型覺得這段文字有多「意外」）當距離」，完全可腳本化、確定性、不需 API，與本產品限制高度吻合，但**效能數字與中文適用性都未取得**【Gap】。

## 本機優先是定位選擇，不是技術護城河：三類誠實分級

### CPU 可行性：規格層級都說得通，端到端延遲沒人測過

所有候選模型的規格都落在筆電 CPU 可跑的範圍：multilingual-e5-small 的 ONNX 版本（一種讓模型在 CPU 上跑得更快的通用格式）在 CPU 上約 920 tokens／秒、比原生快約 2 倍 ([GitHub: tkys/multilingual-e5_onnx](https://github.com/tkys/multilingual-e5_onnx))【有實作但未經評測，硬體規格未附】；緊湊型多語 embedding 模型無批次時 CPU 延遲約 16.6 毫秒 ([Scandinavian Embedding Benchmarks, arXiv:2406.02396](https://arxiv.org/pdf/2406.02396))【有文獻證實，非特定模型】；paraphrase-multilingual-MiniLM-L12-v2 是 118M 參數、384 維 ([Hugging Face](https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2))【有文獻證實】；通用對照是 BERT-Tiny 約 2 毫秒、BERT-base 約 39 毫秒 ([arXiv:2201.00558](https://arxiv.org/pdf/2201.00558))【有文獻證實，間接引用】；sentence-transformers 官方建議 CPU 搭配 optimum／ONNX 後端加速 ([sbert.net](https://sbert.net/docs/sentence_transformer/usage/efficiency.html))【有文獻證實】。但兩件事沒有答案：**「118M 句向量＋0.3B 風格向量＋NER＋規則統計」疊加後的單文件端到端延遲，沒有任何來源測過**【Gap】——「單位數秒內」是線性外推的推論；「pip 可裝、零編譯依賴」也不成立，因為 PyTorch 與 ONNX Runtime 都是預編譯的二進位套件，主流 macOS 不需自己編譯，但不等於零依賴 ([sentence-transformers 安裝文件](https://github.com/huggingface/sentence-transformers/blob/main/docs/installation.md))【有文獻證實】。Q4 筆記的強烈建議：**動工前先花半天在目標 Mac 上實測完整管線**，若疊加後超過 10–20 秒，部分「現在可做」要下修為「理論可做、體驗不佳」。

### 競品全是雲端，沒有一家從「自由改寫」學習且經過驗證

ChatGPT Work 的 Writing style（2026-09-07 上線）讀取已連接的 Gmail、Google Drive、Slack、SharePoint 內容，辨識慣用語、句構、正式程度等模式套用到後續生成 ([WinCentral](https://thewincentral.com/chatgpt-work-learns-your-writing-style/)、[AIPostHub 中文報導](https://www.aiposthub.com/chatgpt-work-learning-writing-style-gmail-slack/))【有文獻證實，多篇獨立報導一致】——所有報導都沒提到從編輯行為學習，它是 sample-based（讀既有文字）而非 edit-based【推論】。Bloomberry 自述從既有貼文萃取「語氣指紋」並「從每一次使用者對生成貼文的編輯中持續學習」 ([Bloomberry Blog](https://www.bloomberry.ai/blog/how-ai-learns-your-writing-voice))【有實作但未經評測，廠商行銷自述】——這是**唯一**明確自述從自由編輯學習的產品，且無第三方驗證。Revise AI 是 accept／reject 二元回饋 ([Revise AI Blog](https://www.revise.net/blog/how-ai-learns-writing-style))【有實作但未經評測】；Grammarly Business 是使用者顯式設定風格指南 ([Grammarly](https://www.grammarly.com/business/styleguide))【有文獻證實】；Microsoft Copilot 的「個人風格指南」是使用者自己寫一份文件當 context 附給模型——本質是 RAG（檢索增強生成：把參考資料塞進 prompt） ([ESPC](https://www.sharepointeurope.com/creating-a-personal-style-guide-for-copilot-for-microsoft-365/))【有文獻證實】；Copilot Tuning 要求至少 20 份檔案做雲端微調，是企業級產品 ([Microsoft Learn](https://learn.microsoft.com/en-us/microsoft-365/copilot/copilot-tuning-style-editing-template))【有文獻證實】。中國市場（豆包、Kimi、文心一言、通義、秘塔、筆靈）**完全沒查到任何「學使用者口吻」的個人化機制**【Gap，未查到≠不存在】。結論：**沒有任何競品聲稱本機運算或本機儲存**【推論，依產品形態判斷】，這是差異化的定位空間；但所有機制描述都來自廠商自述，沒有任何第三方逆向分析【Gap】。

### (草稿, 修改) 對是不是結構性優勢：資料取得是真的，效果與護城河沒被證明

這是本題最核心、也最缺證據的子問題，四個面向要分開判：

**資料取得優勢——真**【推論，有筆記支持】。在 Claude Code／Codex 外掛的形式下，草稿寫進磁碟上的檔案，使用者用自己的編輯器改，工具可以比對前後版本。這讓工具看得到「發生在任何 AI 介面之外的修改」，而 ChatGPT Work、Copilot 等產品公開描述的機制都是讀既有雲端樣本，看不到這類編輯（除非使用者在它們的畫布裡改）。Q4 筆記確認這是「雲端產品在其公開機制描述中沒有做到的事」。

**產品定位優勢——真**【推論】。市場上沒有已知競品選擇本機優先，這是空白的定位，而且「資料全在使用者電腦」對信任是實質的賣點。

**效果優勢——未被證明**【有文獻證實此空白】。CIPHER 沒有「編輯 vs 樣本」的對照組；沒有任何論文或產品做過「同一位使用者、同一批草稿，用編輯歷史個人化 vs 用寫作樣本個人化」的 A/B 實驗【Gap】。目前能說的最強版本是跨論文組合推論：PRELUDE 證明編輯是可用的偏好訊號，LaMP 證明檢索個人歷史能提升個人化 ([LaMP, ACL 2024](https://aclanthology.org/2024.acl-long.399/))【有文獻證實】，所以「本機累積的配對落在已證明有效的檢索增強個人化範式內」【推論】——但沒有任何一篇針對「本機、單一使用者、綁定 coding agent」驗證過。

**技術護城河——假**【推論】。Gboard 的聯邦學習（federated learning：在每台裝置上各自訓練、只把加密的模型更新送回中央彙整，不上傳原始輸入）從 2016 年起就在做裝置端個人化，用於下一字預測、表情符號預測等 ([Google Research Blog](https://research.google/blog/improving-gboard-language-models-via-private-federated-analytics/)、[arXiv:2305.18465](https://arxiv.org/pdf/2305.18465))【有文獻證實】。這證明大廠**完全有能力**做本機學習，甚至規模遠大於單一使用者工具；本機優先是產品定位與商業模式選擇，不是雲端技術上做不到的事。反過來，雲端擁有兩項本機原生做不到的能力：跨使用者先驗知識（從數百萬人的編輯模式學到「大家通常改 AI 草稿的哪裡」）與對模型本身微調；但「跨使用者先驗對單一使用者口吻還原的邊際貢獻」同樣沒有文獻量化【Gap】。

### 外掛形式的天花板：能跑腳本，但不能常駐、不能背景學習

Anthropic 官方工程文件確認 Agent Skill（技能：一個含 SKILL.md 說明檔加上可選腳本的資料夾，代理人需要時載入）可以包含代理人執行的程式碼——PDF skill 內建 Python 腳本讀取表單欄位，代理人執行腳本但不需把腳本或 PDF 內容載入對話 ([Anthropic Engineering](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills))【有文獻證實】。這直接證實「skill 觸發本機 Python 腳本做文體計量與 embedding、再讀回 JSON 結果」的模式可行。MCP（Model Context Protocol：讓代理人連接外部工具的標準介面）生態也有本機 sentence-transformers embedding 伺服器的前例 ([Medium: local MCP server](https://medium.com/@Sanath_raj/i-built-my-own-mcp-server-that-runs-entirely-on-my-laptop-heres-how-19a54c72dd7e)、[qdrant-mcp](https://glama.ai/mcp/servers/andrewlwn77/qdrant-mcp))【有實作但未經評測】。天花板在於：官方文件**沒有處理**「常駐背景程序」「跨對話自動學習」；所有查到的 skill／MCP 案例都是「被呼叫時才執行、執行完就結束」【推論，歸納自案例特徵，非官方明文禁止】。這代表 Gboard 式的「使用者沒叫它、它也在背景持續學」在這個形式下做不到，學習只能在代理人被呼叫的當下發生。單次執行時間與記憶體上限也未查到【Gap】。

| | 「編輯訊號優於寫作樣本」的證據 | CIPHER 無此對照組【有文獻證實此空白】 |

## 結論

這份研究最重要的觀念轉變是：**「像不像本人」不是一個可以外包給 LLM 的判斷，也不是一個可以壓成單一數字的量**。三類指標互不相關、LLM 評審自己抽的特徵每次都不一樣、LLM 生成的文字連「隨機兩個真人的相似度」都達不到——這三個發現合起來說明，目前所有「用 prompt 叫 LLM 模仿」的產品都在一個沒有校準儀器的情況下宣稱成功。本產品能站住的位置，正是把校準儀器做出來：一套確定性的、以字元與功能字為基礎的、對每個 persona 各自建立基準線的多路訊號，加上一份人看得懂的檔案作為所有學習結果的落地處。LLM 仍然負責寫，但它寫完之後要過一道不是 LLM 的關；它學到的東西要寫成人能改的字，不是藏在向量裡。

**關於 Spotify 式突破的誠實判決**：沒有找到。Spotify 之所以是突破，是它解決了一個此前被認為做不到、且可以被量測驗證的具體工程問題（大規模串流秒開）。本研究逐一檢視的六個候選差異化項目——確定性驗證層、內容無關風格向量、編輯記憶檢索、多人格分離、人可讀檔案、本機資料累積——每一項的底層技術都早已存在且個別成熟，沒有一項是「先前做不到、現在做到了」。這個產品的價值是**組合方式與形式因子**的價值：第一次把這些零件放進「本機、代理人外掛、資料不出機、人可讀檔案」這個沒有競品選擇的位置，並用確定性驗證補上 LLM 模仿的已知漏洞。最接近「真差異化」的一項是人可讀口吻檔案作為唯一真相來源，因為它同時有學術論證、有商業先例、且本機版能做到雲端版做不到的完全使用者掌控。「本機累積的 (草稿, 修改) 對」是真實的資料取得與定位優勢，但不是被證明的效果優勢，更不是技術護城河——Gboard 證明雲端廠商想做隨時做得到。這個結論是研究員基於逐項證據的判斷，不是任何文獻的定論；「沒有找到反例」不代表未來不會出現，尤其那條「每位作者一個小型字元級語言模型、用困惑度當距離」的路線，完全符合本產品的限制卻還沒有人給出數字，是最值得下一輪研究追的方向。
