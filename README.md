# Match My Voice

讓 AI 從每個人自己的文字、對話或說話逐字稿，整理個人口吻，再用於寫作與改稿。技能不附帶任何人的個人資料，也不提供聲音複製。

> 目前是繁體中文優先的早期測試版。它提供一套分析與校準流程，不代表已經通過大規模效果驗證。

## 它怎麼運作

1. **Learn**：讀取你主動提供的文章、對話或逐字稿，觀察想法順序、用詞、立場、句子節奏與場合差異。
2. **Calibrate**：先試寫一小段，讓你指出最不像自己的地方。Skill 分辨這是單次修改，還是可重複使用的個人偏好。
3. **Profile**：把確認過的特徵寫進你自己的 `VOICE.md`。這個檔案放在 Skill 外，不會跟著公開儲存庫分享。
4. **Write**：後續寫作時，先保留事實、數字和限制，再用你的口吻檔調整表達。
5. **Refine**：你再次說「這不像我」時，只更新你的口吻檔；不會把你的偏好變成其他人的共用規則。

## 安裝

### Claude Code

```bash
git clone https://github.com/Hunter20041004/match-my-voice.git ~/.claude/skills/match-my-voice
```

### Codex

```bash
git clone https://github.com/Hunter20041004/match-my-voice.git ~/.codex/skills/match-my-voice
```

若 Claude Code 和 Codex 已共用同一個 skills 目錄，只需安裝一份。已有同名資料夾時，先備份自己的修改，不要直接覆蓋。

也可以從 GitHub 下載 ZIP，解壓縮後把完整資料夾放進 AI 工具支援的技能目錄。

宿主如何載入技能取決於工具設定。沒有技能功能時，也可以提供 `SKILL.md` 和 references 目錄的內容，請 AI 遵循。

## 第一次用

直接說「請用 match-my-voice 分析我的口吻」就好。它會先問一句：

> 你想從哪裡拿到你平常怎麼表達的例子？

然後只列出**你這個 AI 工具實際讀得到的來源**。這段對話、貼上文字、回答幾個問題，是不需要任何外部連接就能用的；上傳檔案、選本機資料夾、從已連接的服務挑、語音逐字稿，只有在你的工具支援時才會出現。沒有的東西不會拿出來講。

已經知道要用什麼就直接講，會**跳過**這個問題：

「請用 match-my-voice 分析我的口吻，下面是我自己寫的幾段文字。」

「我沒有樣本，請一次問我一個簡單問題，從我的回答整理口吻。」

選好來源後，它會先把候選的東西列出來、跟你**確認要分析哪些**，並說明會讀什麼、口吻檔會存在哪，才開始分析。選了某個服務不等於授權它翻整個帳號，也不代表可以動你的資料。

它會整理習慣、試寫一小段供你修正，再保存口吻檔。樣本不足時先產生暫定版，不宣稱已完全掌握你的語氣。

建議選擇幾段確定由自己完成、而且自己覺得自然的文字。請避免提供密碼、身分證件、私人聯絡資料或不希望 AI 服務處理的內容。

## 之後使用

「依我的口吻，幫我把這些重點寫成工作信件。」

「這段太正式了，我通常會這樣說……請調整這封信，也更新適用於工作信件的口吻偏好。」

有本機檔案工具時，預設口吻檔放在 `~/.config/match-my-voice/profiles/default/VOICE.md`，與可分享的技能分開。多人、多語言可以各有檔案。沒有檔案功能時，請保存 AI 提供的口吻檔，下次再附上；不保證宿主自動記住。

中文依中文的用詞與句子結構分析，不套英文的分詞統計。這是工作流程設計，尚未完成多使用者、多語言效果測試。是否像你，需要你實際校準。

分享時只分享技能資料夾，不附上 profiles 或私人樣本。模型對資料的處理仍依你使用的 AI 服務而定。

## 幫忙測試

如果你願意參加第一輪測試，請依照 [多人測試規格](docs/first-pilot-zh-TW.md) 操作，或在 GitHub Issue 回報：哪一句不像你、你怎麼修改，以及使用的是哪一種寫作場合。不要把私人原文或完整口吻檔貼到公開 Issue。

## 專案狀態

- 繁體中文優先，其他語言會分開建立口吻檔。
- 個人資料與可公開的 Skill 分離。
- 尚未完成 3～5 位測試者的第一輪盲測。
